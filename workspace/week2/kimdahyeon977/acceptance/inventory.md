# Inventory CLI acceptance contract

Use dependency-free Node.js ESM. Every CLI invocation is a fresh process. `TODO_CLI` points to the CLI in the test runner; `INVENTORY_FILE` selects a JSON store. Success prints exactly one JSON value and exits zero. An error exits nonzero and must not create or change the store bytes. Read-only commands on an absent store return empty data without creating it. Concurrent writers and recovery from externally corrupted JSON are outside this contract.

`item add SKU NAME` registers `{sku,name,onHand:0,reserved:0}`. `item list` returns items in insertion order. SKU must match `^[A-Z][A-Z0-9-]*$` and be unique; NAME must contain non-whitespace text and is stored literally. `stock receive SKU QTY` adds on-hand stock. `stock reserve SKU QTY` moves available stock into reserved stock. `stock release SKU QTY` moves reserved stock back into available stock. `stock ship SKU QTY` subtracts QTY from both on-hand and reserved stock. Each successful mutation returns the updated item. QTY is a canonical positive decimal integer string, at most `Number.MAX_SAFE_INTEGER`, with no leading zeroes or exponent notation. Every resulting count must remain a safe integer. Reserve cannot exceed `onHand-reserved`; release and shipment cannot exceed reserved stock.

`stock report` returns `{items,totalOnHand,totalReserved,totalAvailable}`; `items` is the same insertion-order array as `item list`. Totals are sums over items and `totalAvailable=totalOnHand-totalReserved`. Unknown SKU, unknown commands, wrong argument counts, malformed SKU or QTY, duplicate SKU, invalid NAME, impossible state transitions, and count overflow are errors. These errors preserve existing storage bytes. Separate `INVENTORY_FILE` values are independent.
