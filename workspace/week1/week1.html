01 · 🧩 Project 소개

왜 DeepSeek Harness인가?

우리에게 필요한 건 완성된 Agent를 잘 쓰는 법보다, System Harness부터 직접 만들어보는 경험이었습니다.

DeepSeek Harness
System Harness부터
직접 만들어볼 수 있습니다.
Minimal Agent를 baseline으로 두고, Agent가 어떻게 생각하고 어떤 능력을 가지는지 결정하는 시스템 레이어를 하나씩 조립합니다.
Modelbaseline
System Promptrole · behavior
Tool Runtimewhat it can do
Context / Memorywhat it can see
Permissionwhat it may do
Agent Loop / Workflowhow it acts
하나씩 붙여가며 어떤 요소가 성능을 바꾸는지 직접 확인할 수 있습니다.

그래서 무엇을 만들어볼까?

우리가 만든 Agent를 기존 Agent와 비교하면서 네 가지 목표를 확인합니다.
01 · OUTPUT

비슷한 결과를 만들기

특정 Task에서 Claude Code나 Codex 같은 기존 Agent와 비슷한 수준의 output을 만들어봅니다.

02 · RUNTIME

더 빠르게 수행하기

필요 없는 과정과 Tool call을 줄여 특정 Task의 runtime을 줄여봅니다.

03 · TOKEN

더 적은 Token 쓰기

불필요한 Context와 Prompt를 줄이면서도 성능을 유지할 수 있는지 확인합니다.

04 · CAPABILITY

더 적은 Tool과 권한으로 수행하기

Task에 꼭 필요한 Capability만 남겨도 같은 수준으로 잘 동작하는지 실험합니다.

📦 구성 자체가 명확해지면, 다른 사람에게 공유하고 다른 환경에 이식하기도 쉬워집니다.
DeepSeek Harness를 선택한 이유는 System Harness 레벨에서부터 실험할 수 있기 때문입니다. 이번 스터디에서는 단순히 output만 보는 게 아니라, 비슷한 품질을 유지하면서 runtime, token, 사용 Tool과 권한을 얼마나 줄일 수 있는지도 같이 봅니다.

04 · 🛠️ Week 1 · Set Up

Standard vs Minimal

같은 Model을 쓰더라도, Agent에게 주어진 Harness는 꽤 다릅니다.

Standard

Rich Harness
구조화된 Tool과 Planning / Skill / Delegation까지 포함된 비교적 풍부한 구성
  • Filesystem
  • FS Search
  • Bash / Pwsh
  • Web
  • Skills
  • Planning
  • Subagent
  • Todo / Ask User

파일을 읽고 검색하는 전용 Tool, Web, Skill, 계획과 delegation까지 제공됩니다. 같은 Task라도 “어떻게 접근할지”에 Harness가 개입할 여지가 큽니다.

Minimal

Lean Harness
가벼운 Persona와 persistent shell을 중심으로 한 최소 구성
  • Persistent Shell
  • Terminal
  • Light Persona
  • No Runtime Context

대부분의 작업을 shell 명령으로 해결해야 합니다. 결과가 비슷하게 나오더라도 Tool 선택과 행동 경로가 Standard와 다를 가능성이 큽니다.

여기서는 “Standard가 더 좋다”라고 결론내리지 않습니다. Task에 따라 Minimal이 더 단순하고 효율적일 수도 있다는 점을 열어둡니다.
