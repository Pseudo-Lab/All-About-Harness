# Transaction ledger CLI acceptance contract

Use dependency-free Node.js ESM. Every invocation is a fresh process. `TODO_CLI` points to the CLI in the test runner; `LEDGER_FILE` selects a JSON store. Success prints exactly one JSON value and exits zero. An error exits nonzero and must not create or change store bytes. Read-only commands on an absent store return empty data without creating it. Concurrent writers and recovery from externally corrupted JSON are outside this contract.

`ledger import CSV_PATH` reads a UTF-8 CSV file with the exact header `id,date,amount,category` and one record per physical line, using LF or CRLF. A CSV field may be quoted, contain commas, and escape a quote as `""`; embedded newlines are not supported. Every row must have exactly four fields. Blank lines between records are invalid; a final line terminator is allowed. ID matches `^[A-Z][A-Z0-9-]*$`. Date is a real calendar day in canonical `YYYY-MM-DD` form, including leap-year rules. Amount is a nonzero, signed, safe integer number of cents written as a canonical decimal string: no plus sign, leading zeroes, decimal point, or exponent notation. Category is stored literally but must contain non-whitespace text. The sum of imported amounts must also stay a safe integer.

An import is atomic: validate every row and all duplicate relationships before changing the store. A repeated ID with identical `{id,date,amount,category}` is skipped; a repeated ID with different data rejects the entire import. On success return `{added,skipped,total}`, where total is the current number of stored rows. An import that adds zero rows leaves the store bytes unchanged. `ledger list` returns rows in first-import order. `ledger summary` returns `{count,total,byCategory}` for all rows. `ledger summary FROM TO` returns the same structure for the inclusive date interval; both dates must be valid and FROM must be no later than TO. Category totals are signed cents. `ledger delete ID` removes an existing row and returns that row; a second deletion fails. Unknown commands, missing or extra arguments, invalid CSV or dates, missing files or IDs, and invalid summaries are errors that preserve existing storage bytes. Separate `LEDGER_FILE` values are independent.
