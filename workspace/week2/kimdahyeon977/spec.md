# 검증 기반 Coding RALPH 명세

## 목표

DeepSeek Harness Creator Mode에서 Custom Plugin과 Preset을 구성한다. Plugin이 공식 `tool-ralph`를 호출하지 않고 구현과 독립 검증의 반복을 직접 제어한다. grill-me 인터뷰에서 사용자가 아래 범위를 확정했다.

## 동작

1. 사람이 요구사항, 계획, 고정 테스트를 확정한다.
2. 구현 Child Agent가 공유 Workspace에서 구현하거나 수정한다.
3. 별도의 새 테스트 Child Agent가 고정 테스트를 실행하고 결과를 보고한다.
4. 실패 결과와 이전 구현 보고를 다음 Round에 전달한다.
5. 모든 테스트가 통과하면 완료한다. 최대 5 Round까지 실패하면 미완료로 종료한다. 테스트 실행 환경 오류는 원인을 기록하고 중단한다.

각 Child는 새 대화를 사용한다. 작업 파일은 공유한다. 구현 에이전트의 완료 선언만으로 완료를 판단하지 않는다. 테스트 변경은 허용하지 않으며 변경을 감지하면 중단한다. 취소와 Child 실행 실패도 성공으로 처리하지 않는다.

## 예제 CLI

Node.js ESM, 외부 의존성 없이 `node cli.mjs add TITLE`, `list`, `complete ID`를 지원한다. `TODO_FILE` 경로에 JSON으로 저장한다. 성공 출력은 JSON이며 실패는 0이 아닌 종료 코드다. 추가 결과는 `{id,title,completed:false}`, 조회 결과는 배열, 완료 결과는 `completed:true`인 항목이다. ID는 양의 정수로 안정적으로 증가한다.

빈 제목, 잘못된 ID, 존재하지 않는 ID는 오류다. 새 프로세스에서도 상태가 유지되고 잘못된 명령은 저장 내용을 변경하지 않는다.

## 검증 항목

- CLI: 빈 목록, 추가와 조회, 다중 추가, 완료 처리, 재실행 후 유지, 빈 제목과 잘못된 ID 거부, 오류 시 상태 보존.
- Plugin: 구현과 테스트 분리, 실패 보고 전달, 통과 시 종료, 5 Round 한도, 환경 오류 중단, 취소 전달, Child 정리, 고정 테스트 변경 거부.
- 통합: 실제 Plugin 등록과 호출, Preset 로딩, 로그 보관.
- 비교: 동일 모델·지시문·초기 파일·최대 5 Round로 Custom과 공식 `tool-ralph` 실행. 최종 결과는 동일한 고정 테스트로 평가한다.

## 계획

1. 이 명세와 acceptance 테스트를 먼저 작성한다.
2. 독립적으로 검증 가능한 반복 제어 모듈과 Harness 어댑터를 구현한다.
3. Creator Mode 설치 및 Preset 사용 경로를 준비한다.
4. 별도 서브에이전트가 테스트를 실행한다. 실패하면 구현을 수정하고 재검증한다.
5. 실제 Custom·공식 실행 로그와 비교 결과를 남긴다. 실행하지 못한 항목은 통과와 구분한다.
